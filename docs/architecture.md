# TD4のCPU・信号モデル

## 基本構成

TD4は4bitレジスタA/B、4bitのPC、キャリーフラグ、4bit入力スイッチ、4bit LED出力、16×8bit ROMから構成されます。本実装はCPUを命令単位で模擬し、元の74HC153に基づく入力MUXと4bit加算の動作を再現します（非公式な命令バイトも含む）。

命令バイトを上位4bit `op`、下位4bit `im` とすると：

```
selectorA = ((op >> 3) & 1) | (op & 1)
selectorB = (op >> 1) & 1
source = [A, B, IN, 0][selectorB * 2 + selectorA]
sum = source + im
result = sum & 0xF
nextCarry = sum > 0xF ? 1 : 0
```

`op >> 2` により書込先がA/B/OUT/PCに選択されます。JNCは**実行前のC**を参照し、C=0のときだけジャンプします。Cは各命令で加算結果から更新されます。

## ボード表示

CSSベースのボードに、PC、ROM、A/Bレジスタ、ALU、出力ラッチ、LED、スイッチ、CLK、Cを機能ブロックとして配置しました。SVG配線は`data-wire`が指す**単一のビット**の信号を表し、Hなら明るい緑、Lなら暗い緑です。バス4bitを「全部HまたはL」と誤解させないよう、配線は`PC0`、`D0`、`IN0`、`OUT0`等に対応します。実物のプリント基板の形状・配線とは異なります。

## クロックと波形

クロックは低レベルLと高レベルHを交互に切り替えます。**L→H**で`cpu.step()`が1回呼び出されます。H→Lではレジスタ・LED出力は変化しません。手動ステップはHを約180ms表示してからLに戻します。

`src/core/signals.ts` の `snapshot(cpu, clockHigh)` が次の論理値を取得します。

- CLK、C
- A0〜A3、B0〜B3、PC0〜PC3
- IN0〜IN3、OUT0〜OUT3
- D0〜D7（現在PCのROMデータ）
- ALU0〜ALU3（現在PCの命令で行われる組み合わせ加算結果）

選択した信号グループごとに、直近80サンプルをSVGのステップ波形で描画します。長期連続実行でもメモリ使用量は固定で、画面再描画は高クロック時に制限します。スイッチ操作で非同期に入力が変化した場合も1サンプル記録します。

これらは**理想論理レベル**であり、実機のクロックデューティ、伝搬遅延、チャタリング、電圧やグリッチは表しません。時間軸は一律のサンプル順で、実時間の秒ではありません。

## サンプルプログラム

`src/data/samples.ts` にROMに収まる8種類のサンプルを収録しています。画面上部の6カードはROMロードと実行をワンクリックで行います。プログラムエディタのプルダウンから8種類すべてを選択できます。

## ファイル依存

読み込み順は`assets/js/core/td4-core.js` → `assets/js/data/samples.js` → `assets/js/core/signals.js` → `assets/js/ui/app.js`です。いずれもJavaScriptで、外部サービスへのアクセスは必要ありません。

## TypeScript移行・GitHub Pagesデプロイ

開発用ソースは `src/{core,data,ui,types}/`、公開用JavaScriptは `assets/js/`、スタイルは `assets/css/` です。

- `npm run build` で `tsc` が `src/` 配下のTypeScriptを対応する `assets/js/` 配下へコンパイルします。
- 既存HTMLの `<script defer>` 参照と CommonJS互換（Nodeの `require()` でテスト）は変更しません。
- `strict` な型チェックにより、4bit CPU状態・命令履歴・ROM・アセンブル結果・各種H/L信号・ブラウザDOM操作を検証します。
- 実行時依存ゼロ、DOM/SVGレイアウト・LED・スイッチ・波形・サンプルの動作を維持します。
- GitHub Actionsがmainとdevelopの `index.html` と `assets/` を検証して、`/td4/` と `/td4/develop/` にまとめて配信します。PagesのSourceはGitHub Actionsに設定してください。詳細は [デプロイ手順](deployment.md) に記載しています。
- `.js` は生成物なので直接編集せず、TypeScriptを更新して `npm run verify` 後にソースと生成物を一緒にコミットします。

## ディレクトリ変更時の注意

`tsconfig.json` の `rootDir` が `src`、`outDir` が `assets/js` のため、TypeScriptのディレクトリ階層が生成物にもそのまま反映されます。HTMLの4つの `<script defer>` は依存順を維持してください。`assets/js/` のファイルは手作業で変更せず、`npm run verify` で再生成してください。

## ICレベル回路モデル（2026年11月）

- 13個の74HCパッケージを機能単位で可視化：74HC161×4、74HC153×2、74HC283、74HC74、74HC32、74HC10、74HC14、74HC154、74HC540。
- `src/core/ic-circuit.ts` がICごとの機能信号（ピン名ラベル）と論理ネットを定義し、`levels(cpu, clock)` から現在の0/1を計算する。
- `src/ui/app.ts` がIC/DIPカードとネット接続SVGを構築し、ROM/入力/出力/クロックの変化時に同期表示する。
- ROM 16×8bitは`cpu.rom`と双方向に連動。アドレスランプは74HC154の負論理選択出力(`/ROMn` = 0)で点灯。
- ROMの生バスは負論理の`ROM_RAW0..7`で、74HC540を介したCPU命令バス`D0..7`はその反転値。
- MUX選択: `SEL_A=D4 OR D7`、`SEL_B=D5`。4bit ALUの`COUT`と74HC74に保持された`C`は別信号。
- レジスタ書込制御は負論理: `LOAD_A_N=D6 OR D7`、`LOAD_B_N=!D6 OR D7`、`LOAD_OUT_N=!D7 OR D6`、`LOAD_PC_N=!(D6 AND D7 AND (D4 OR !C))`。JNC判定に使うCは前クロックのキャリーフラグ。

### スコープと精度

この画面の IC ピンラベルは**論理上の機能信号**を示し、部品の実ピン番号や配線ルートを一対一対応させるものではありません。選択された一つの信号ネットに接続する表示点をSVGで結んでいます。実物の基板の完全なネットリスト・実際のパッケージのすべてのピン・未使用ゲート/電源配線・抵抗/ダイオードは未再現です。実装を実回路図の詳細シミュレータへ発展させる際は、ユーザーのKiCad回路図/ネットリストに置き換える必要があります。

参照: [Kevin's Blog: TD4 architecture](https://emalliab.wordpress.com/2025/09/18/td4-4-bit-diy-cpu/) および [TD4 4-bit DIY CPU – Part 2](https://emalliab.wordpress.com/2025/09/28/td4-4-bit-diy-cpu-part-2/)。

## ICの端子レイアウト

物理パッケージのピン本数（74HC154=24、74HC540=20、74HC153/283/161=16、74HC74/32/10/14=14）に応じた左右のピン形状を描きます。信号プローブは機能別配置であり、物理ピン番号と信号の対応は未提供です。74HC154および74HC540は入力左・Y出力右、74HC153は上下に回路1/回路2、74HC283は右列にSUMとCOUTをまとめます。

## DIPパッケージの表示スケール

ICカードは4列表示とし、物理パッケージは**2.54mmを18px**に換算した共通の画面スケールで描画します。DIP-14/16/20/24は左右それぞれ7/8/10/12本のピンを一定間隔で配置し、外形長さを126/144/180/216pxに設定します。一般的なナローDIPは両ピン列間7.62mm相当（54px）、74HC154も表示上のピン列間隔を他ICと同じ54pxへ揃えます（実際のワイドDIPの寸法比を厳密に再現する設定ではありません）。画面の表示倍率・DPIを固定するものではなく、各部品間の**寸法比**を合わせるためのスケールです。

物理ピン列の表示と、各ICの機能に沿って左右にまとめたH/Lプローブは**別の表現**です。機能プローブは実際のパッケージ端子番号への結線表を意味しません。74HC154など出力端子が多いICでも、物理パッケージを無理に伸縮せず、機能プローブ側で必要な行数を確保します。

### DIPパッケージのピン表示

全ICは左右のピン列を同じ間隔（画面上54px）に統一し、ピン数に応じた縦方向の長さだけ変更します。通常はIC上面の型番と物理ピン列だけ表示し、IC本体をクリック／Enter／Spaceで機能信号プローブを展開できます。物理ピンはデータシートの番号と一致するところだけCPU信号モデルに結び付け、**H=緑、L=灰色**で着色します。簡易モデルが信号を扱っていないピンは、Lと誤認しないよう縞模様で未モデル化と区別します。機能端子のH/L詳細はクリック後に既存どおり利用できます。74HC32/10/14のゲート内部結線を推定した値は割り当てません。厳密な基板上の各脚の状態はCADのネットリストを取り込んでから確定できます。
