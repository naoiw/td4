# TD4 設計・実装仕様

利用方法は[操作ガイド](usage.md)、物理端子とネットの確定状況は[ネットリスト](netlist.md)、CIと公開手順は[開発・デプロイ](deployment.md)を参照してください。

## 基本構成

TD4は4bitレジスタA/B、4bitのPC、キャリーフラグ、4bit入力スイッチ、4bit LED出力、16×8bit ROMから構成されます。本実装はCPUを命令単位で模擬し、元の74HC153に基づく入力MUXと4bit加算の動作を再現します（非公式な命令バイトも含む）。

命令バイトを上位4bit `op`、下位4bit `im` とすると：

```
selectorA = ((op >> 3) & 1) | (op & 1)
selectorB = (op >> 1) & 1
source = [A, B, IN, 0][selectorB * 2 + selectorA]
sum = source + im
result = sum & 0xF
nextCarry = sum > 0xF ? 1 : 0
```

`op >> 2` により書込先がA/B/OUT/PCに選択されます。JNCは**実行前のC**を参照し、C=0のときだけジャンプします。Cは各命令で加算結果から更新されます。

## ボード表示

CSSベースのボードに、PC、ROM、A/Bレジスタ、ALU、出力ラッチ、LED、スイッチ、CLK、Cを機能ブロックとして配置しました。選択したネットはHIGH時にオレンジ、LOW時に淡い黄色で強調表示します。H/Lは別の表示であり、選択の強調色と混同しません。実物のプリント基板の形状・配線とは異なります。

## クロックと波形

クロックは低レベルLと高レベルHを交互に切り替えます。**L→H**で`cpu.step()`が1回呼び出されます。H→Lではレジスタ・LED出力は変化しません。現行UIでは手動ステップは提供せず、基板の2Hz／10Hzスイッチで自動クロックを切り替えます。

`src/core/signals.ts` の `snapshot(cpu, clockHigh)` が次の論理値を取得します。

- CLK、C
- A0〜A3、B0〜B3、PC0〜PC3
- IN0〜IN3、OUT0〜OUT3
- D0〜D7（現在PCのROMデータ）
- ALU0〜ALU3（現在PCの命令で行われる組み合わせ加算結果）

信号グループは基本信号・入出力・レジスタA/B・PC / ALU・ROMの5種類です。PC / ALUは `CLK, C, PC3, PC2, PC1, PC0, ALU3, ALU2, ALU1, ALU0` の10信号をまとめて表示します。各グループを10信号以下（レジスタA/BとPC / ALUは10、ROMは9）に制限し、波形領域には常に10行分の枠を表示し、未使用チャンネルは「-」・状態「×」として波形とグリッド線を描きません。10行はグリッドで等分配置し、最上段と最下段の上下余白が同じになるようにします。縦スクロールはありません。隣のEXECUTION TRACEは同じ550pxのパネル高さに固定し、実行履歴のみ内部スクロールします。各信号の直近80サンプルをSVGのステップ波形で描画します。長期連続実行でもメモリ使用量は固定で、画面再描画は高クロック時に制限します。波形取得方式は `WaveCaptureMode = 'cpu' | 'oscilloscope'` の内部設定（初期値 `oscilloscope`）で管理します。`cpu` モードは電源ONかつCPU実行中のクロック/入力操作でのみサンプルを追記し、CPU停止中のINPUT操作では現在のH/L表示と基板は更新するものの、波形履歴は凍結します。信号グループを切り替えるか「波形を消去」を押した際は履歴をクリアし、CPU停止中なら再実行時まで空欄とします。`oscilloscope` モードはCPUのクロックと独立した20ms（50サンプル/秒）のタイマーで電源ON中に連続サンプリングし、CPU停止中はCPU内部信号の論理値を保持した水平波形として記録します（INPUTが非同期に変化した場合は入力イベントで即時に変化点を記録し、次の取得周期以降も変化後の論理値を保持して表示）。電源OFF時はタイマーを停止します。切替は画面に露出せず、`window.TD4WaveCapture.setMode('cpu' | 'oscilloscope')` と `getMode()` で内部的に操作できます。オシロスコープはCLKの最大10Hz（1周期100ms）を5サンプル/周期で記録し、2Hz（1周期500ms）は25サンプル/周期となるので、実際の5倍の周期差を波形で確認できます。波形取得は20msごとに継続しつつSVG描画は40ms以上の間隔に抑えます。80サンプルの表示時間幅は約1.6秒です（INPUTの即時変化点記録時は時間軸がサンプル基準のため厳密な等間隔ではありません）。両モードとも直近80サンプルで制限し、CPUの実行状態やROM内容には影響を与えません。

これらは**理想論理レベル**であり、実機のクロックデューティ、伝搬遅延、チャタリング、電圧やグリッチは表しません。時間軸は一律のサンプル順で、実時間の秒ではありません。

## サンプルプログラム

`src/data/samples.ts` にROMに収まる9種類のサンプルを収録しています。画面上部の6カードはROMロードと実行をワンクリックで行います。プログラムエディタのプルダウンから9種類すべてを選択できます。詳しい操作例は[操作ガイド](usage.md)に記載します。

PROGRAM ROMとPROGRAM EDITORは同じ`detail-grid`に配置し、横並び時は`align-items:stretch`で両パネルの高さを統一します。狭い画面で1列になる場合はコンテンツごとの高さに戻ります。ROMの.binファイル保存・読込UIおよびイベント処理は撤去しましたが、サンプルのROMロード、アセンブル、ROM直接編集、「ROM → ソース」機能は維持します。

### 16命令のスイッチ入力デモ

`echo` は8組の `IN B`（機械語 `0x60`）と `OUT B`（`0x90`）でROM全16番地を使用します。4bit PCは番地 `0xF` を実行すると次に `0x0` へオーバーフローするため、`JMP` は不要です。旧3命令ループよりもLEDの更新間隔が3クロックから2クロックに短縮されます。`IN B` で読んだ値をBレジスタに保持するため、直後の `OUT B` までにINPUTを変更しても、その出力には前回読んだ値が表示されます。

### 16バイトの2進ウェーブデモ

`bounce` はROMの `0x0`〜`0x7` に左向きウェーブ `B1,B3,B7,BF,B7,B3,B1,B0`、`0x8`〜`0xF` に右向きウェーブ `B8,BC,BE,BF,BE,BC,B8,B0` を配置します。全バイトが `OUT n`（`0xBn`）で、前半／後半の終端では `OUT 0` により1クロック消灯します。4bit PCは最終アドレス `0xF` の実行後に `0x0` へ戻るため、`JMP` による停止時間の偏りはありません。指定ROMバイト列・16クロック×2周の出力・PC折り返しを自動テストします。

### 16命令の2bit加算デモ

新サンプル `sum2` は `SW1:0` と `SW3:2` を2bit数として加算し、`LED2:0` に出力します。入力値 `x = SW3..0` をもとに、4bitのAレジスタで `x >= 12`、`x >= 8`、`x >= 4` を `ADD A,4` のキャリーと `JNC` で判定し、Bレジスタにそれぞれ `+7`、`+10`、`+13`、`+0` を加えます（4bit環状演算）。結果は `(x & 3) + (x >> 2)`、0〜6になります。最後の `ADD B,12` は結果が4以上のときCPUのCフラグを1にするための処理で、**Cはこの1クロックだけ桁上がりを示し、次のJMPで更新されます**。全16命令は分岐先・結果出力・桁上がり確認・ループ復帰に使用します。SW入力16通りの結果と、全0〜F番地への到達はテストで検証します。

## TypeScript移行・GitHub Pagesデプロイ

開発用ソースは `src/{core,data,ui,types}/`、公開用JavaScriptは `assets/js/`、スタイルは `assets/css/` です。

- `pnpm run build` でネットリスト用JavaScript生成と `tsc` によるTypeScriptコンパイルを実行し、対応する `assets/js/` 配下へ出力します。
- 既存HTMLの `<script defer>` 参照と CommonJS互換（Nodeの `require()` でテスト）は変更しません。
- `strict` な型チェックにより、4bit CPU状態・命令履歴・ROM・アセンブル結果・各種H/L信号・ブラウザDOM操作を検証します。
- 実行時依存ゼロ、DOM/SVGレイアウト・LED・スイッチ・波形・サンプルの動作を維持します。
- GitHub Actionsがmainとdevelopの `index.html` と `assets/` を検証して、`/td4/` と `/td4/develop/` にまとめて配信します。PagesのSourceはGitHub Actionsに設定してください。詳細は [デプロイ手順](deployment.md) に記載しています。
- `.js` は生成物なので直接編集せず、TypeScriptを更新して `pnpm run verify` 後にソースと生成物を一緒にコミットします。

## ディレクトリ変更時の注意

`tsconfig.json` の `rootDir` が `src`、`outDir` が `assets/js` のため、TypeScriptのディレクトリ階層が生成物にもそのまま反映されます。HTMLの7つの `<script defer>` は依存順を維持してください。`assets/js/` のファイルは手作業で変更せず、`pnpm run verify` で再生成してください。

## ICレベル回路モデル（2026年11月）

- 13個の74HCパッケージを機能単位で可視化：74HC161×4、74HC153×2、74HC283、74HC74、74HC32、74HC10、74HC14、74HC154、74HC540。
- `src/core/ic-circuit.ts` がICごとの機能信号（ピン名ラベル）と論理ネットを定義し、`levels(cpu, clock)` から現在の0/1を計算する。
- `src/ui/board.ts` がIC/DIPカード・ROMスイッチを構築し、H/L表示とネット選択のオレンジ色ハイライトを同期描画する。`src/ui/app.ts` はCPUの実行・状態変更と画面更新の呼び出しを管理する。
- ROM 16×8bitは`cpu.rom`と双方向に連動。アドレスランプは74HC154の負論理選択出力(`/ROMn` = 0)で点灯。
- ROMの生バスは負論理の`ROM_RAW0..7`で、74HC540を介したCPU命令バス`D0..7`はその反転値。
- MUX選択: `SEL_A=D4 OR D7`、`SEL_B=D5`。4bit ALUの`COUT`と74HC74に保持された`C`は別信号。
- レジスタ書込制御は負論理: `LOAD_A_N=D6 OR D7`、`LOAD_B_N=!D6 OR D7`、`LOAD_OUT_N=!D7 OR D6`、`LOAD_PC_N=!(D6 AND D7 AND (D4 OR !C))`。JNC判定に使うCは前クロックのキャリーフラグ。

### スコープと精度

この画面の IC ピンラベルは**論理上の機能信号**を示し、部品の実ピン番号や配線ルートを一対一対応させるものではありません。選択された信号ネットに属するICの足、ROM左上の選択ランプ、ROMデータスイッチ、INPUT/OUTPUT部品をHIGH時はオレンジ色、LOW時は淡い黄色で強調し、選択ネット間のSVG線は描画しません。実物の基板の完全なネットリスト・実際のパッケージのすべてのピン・未使用ゲート/電源配線・抵抗/ダイオードは未再現です。実装を実回路図の詳細シミュレータへ発展させる際は、ユーザーのKiCad回路図/ネットリストに置き換える必要があります。

参照: [Kevin's Blog: TD4 architecture](https://emalliab.wordpress.com/2025/09/18/td4-4-bit-diy-cpu/) および [TD4 4-bit DIY CPU – Part 2](https://emalliab.wordpress.com/2025/09/28/td4-4-bit-diy-cpu-part-2/)。

## ICの端子レイアウト

物理パッケージのピン本数（74HC154=24、74HC540=20、74HC153/283/161=16、74HC74/32/10/14=14）に応じた左右のピン形状を描きます。信号プローブは機能別配置であり、物理ピン番号と信号の対応は未提供です。74HC154および74HC540は入力左・Y出力右（74HC540はA/Yをそれぞれ4行×2列に並べ、左列0～3・右列4～7）、74HC153は上下に回路1/回路2を設け、各回路のINPUT側にS0/S1（左列）とA・B・IN（右列）を表示します。74HC283はOUTPUT側にSUM0〜SUM3（左列）とCOUT（右列）を表示します。

## DIPパッケージの表示スケール

ICは左列の制御・MUX/ALU・レジスタエリア（上から順）と、中央の74HC154/540縦列に並べます。物理パッケージは**2.54mmを18px**に換算した共通の画面スケールで描画します。DIP-14/16/20/24は左右それぞれ7/8/10/12本のピンを一定間隔で配置し、外形長さを126/144/180/216pxに設定します。一般的なナローDIPは両ピン列間7.62mm相当（54px）、74HC154も表示上のピン列間隔を他ICと同じ54pxへ揃えます（実際のワイドDIPの寸法比を厳密に再現する設定ではありません）。画面の表示倍率・DPIを固定するものではなく、各部品間の**寸法比**を合わせるためのスケールです。

物理ピン列の表示と、各ICの機能に沿って左右にまとめたH/Lプローブは**別の表現**です。 IC詳細画面では全13個のICについて信号プローブを共通の最大幅112px・高さ42px・文字12pxに統一します。各IC固有の入力／出力の位置、4×4や4×2の配列、複数回路の順序は変更せず、1セクションのICは詳細パネルの横幅を活用します。機能プローブは実際のパッケージ端子番号への結線表を意味しません。GND/VCCへ固定されたイネーブル端子（74HC154のG#、74HC540のOE#、74HC153のE#）はIC詳細の機能プローブから省略します。74HC161（U3〜U6）の詳細INPUTは左列をCLK・PE#、右列をD0〜D3とする2列配置にします。動的な74HC161のPE#は表示を維持しますが、固定LOWの74HC153入力C3と74HC283のCIN（C0）、およびモデル上HIGH（リセット非アクティブ）に保持する74HC74と74HC161のCLR#はIC詳細から省略します。物理DIP脚と`netlist.json`の結線情報は変更しません。74HC154など出力端子が多いICでも、物理パッケージを無理に伸縮せず、機能プローブ側で必要な行数を確保します。

### DIPパッケージのピン表示

全ICは左右のピン列を同じ間隔（画面上54px）に統一し、ピン数に応じた縦方向の長さだけ変更します。通常はIC上面の型番と物理ピン列だけ表示し、IC本体をクリック／Enter／Spaceで機能信号プローブを展開できます。物理ピンはデータシートの番号と一致するところだけCPU信号モデルに結び付け、**H=緑、L=灰色**で着色します。簡易モデルが信号を扱っていないピンは、Lと誤認しないよう縞模様で未モデル化と区別します。機能端子のH/L詳細はクリック後に既存どおり利用できます。74HC32（4個のORゲート）と74HC10（3個のNANDゲート）の全入力・出力は添付PDFに基づいて結線を確定し、各ゲートの詳細プローブも `netlist.json` の物理ピンに追従します。74HC14の未使用ゲートや受動素子など、PDFからまだ確定できない部分は推測で結線しません。

## コンパクト基板レイアウト

機能別区画を左列3段と中央のROM/FETCH列に配置し、ICをDIP外形だけで密集表示します。区画は「ROM/FETCH」（ROMデコーダ/バッファ）、「MUX/ALU」（2個の74HC153と74HC283）、「REGISTERS」（4個の74HC161）、「CLOCK/CONTROL」（74HC74・32・10・14）の4区画です。IC単体のカード枠は表示せず、機能別区画の見出しと境界だけを基板上に示します。クリック時は基板外の詳細パネルに入出力・H/Lプローブを表示するため、通常の基板サイズは変わりません。脚の2.54mmピッチ、各物理ピンと信号のH/Lの対応、ROMの4行×4列とInput/Output横並び配置を維持しています。

## ROM 4×4と基板外IC詳細

16アドレスのROMを4行×4列で表示し、基板ROMとPROGRAM ROMの番地ラベルはどちらも `0x0`〜`0xF` 形式とします。各8bit DIPスイッチは横向き（D7が左、D0が右）に配置します。InputとOutputはROM下に横並びに設置します。機能別に区画された13個のICは基板左側に縦長のDIPとして配置します。クリック時にはIC詳細を基板の外側（`icDetailPanel`）へ移し、パネルを拡大表示します。これにより基板と詳細が重ならず、別のICをクリックすると表示内容が切り替わります。物理脚のH/LとCPUのROM/IO動作は従来どおりです。

## PCBの外観

基板領域には緑色のレジスト風背景（`#166342`）を使用し、基板の外側は白背景です。四隅の取付穴はクリック不可の装飾要素（`pcb-mount-hole`）で、白い貫通穴と金属リングを模した描画です。ROMの各8bit DIPスイッチは4×4マトリクスを保ったまま横向きに表示し、8個のハンドルが上下にスライドします。論理ビットのデータと操作は変更しません。

## FETCH/ROM 中央縦列（2026-11）

4区画のうち、左列には CLOCK/CONTROL（74HC74・32・10・14）、MUX/ALU（74HC153×2、74HC283×1）、REGISTERS（74HC161×4）を上から順に配置します。中央の細い縦列（ROM/FETCH）に置くのは **74HC154 と 74HC540 の2個のみ**で、DIPの左右2列にピンを配置し、H/L表示を維持します。 ICリファレンス（U番号）は11px・太字の明るいシルク文字とし、パッケージ本体との間にはヘッダー高さ18px・本体上マージン6pxで余白を確保し、左列3ブロックの内側余白を広げています。ROM/FETCHの2つのICは縦領域全体に分散し、最小28pxの間隔を保ちます。ROMの16個の8bit DIPスイッチは右側の4×4（行順0〜F）のままです。基板上端の装飾的なLogic ICs/ROMの見出しと、基板下のHIGH/LOW・アドレス選択凡例や注意書きは削除しています。緑色基板・白背景・四隅の取付穴を維持します。

## 基板DOMの分離

`src/ui/board.ts` はDIP脚・機能別エリア・ROM 4×4スイッチ・Input/Outputの**DOM生成とH/L・選択端子の強調表示**を担当します。`src/ui/app.ts` はCPU状態・ROM編集・実行制御・IC詳細を管理します。イベントは `BoardViewOptions` のコールバックを通してアプリ側で処理します。公開JSの読み込み順は `ic-circuit.js` → `board.js` → `app.js` です。

基板表示モジュールの `render({cpu, circuit, clockHigh, selectedNet})` はIC脚・ROMスイッチ・入出力LED・選択信号ラベルを同期し、選択ネットは`render()`で同一ネットの端子・ランプ・部品にオレンジ色の強調を適用します。CPU状態の読み取りは行いますが、CPU命令実行やROM書換えは行いません。

基板CSSの整理では、同一セレクタ／同一条件で**後続の宣言に完全に上書きされる宣言**だけを削除しています。適用される最終プロパティと値が一致することを機械的に照合し、カスケード順・DIP寸法・ROMの4×4配置・基板の基本配色は変更していません。

## 基板の信号色とROM表示

物理DIP脚は電源端子名が`VCC`なら電源ON時は赤、OFF時は明るい赤の発光を消して暗い灰緑色に切り替えます（実装上の名称はVCC。VDDに相当する正側の電源端子）。`GND`は黒を優先します。残りの論理信号ピンのみ、現在のH=緑・L=灰色で表示します。電位をモデル化していない／NC表示相当の脚は暗灰色にします（未モデル化の実ピンが物理的に未接続であるという意味ではありません）。ROMアドレス選択LEDは緑色、8bit DIPスイッチ下は左端「7」・右端「0」で配置します。INPUT/OUTPUTの論理状態もH=緑・L=灰色に統一します。

## CYCLESカウンタ

クロックの立ち上がりで命令を実行するごとにCYCLESを1加算し、`999999`の次は`000000`に折り返します。内部カウンタも100万を法とする6桁の循環カウンタです。停止・再開では維持し、CPUリセット時は`000000`になります。表示は常に6桁で、CPUのPCやROMの挙動には影響しません。

## 基板のウィンドウ追従表示

基板の論理的な描画幅は1135pxのまま維持し、親の`.schematic-scroll`の利用可能幅を基に`transform: scale(...)`で等倍率に縮小・拡大します。通常の縮尺計算は上限1.2倍・利用可能幅での自動フィットとします。デスクトップでウィンドウがモニター利用可能幅の85%以上かつ幅1100px以上のときだけ、計算された倍率を0.8倍にして大型モニターの全画面で基板を小さめに表示します。半幅ウィンドウなど、それ以外の幅では以前の倍率をそのまま維持します。親の高さも縮小後の高さへ追従させ、不要な余白を作りません。画面サイズとコンテナ幅、基板の内容高さの変化を`ResizeObserver`と`resize`イベントで監視します。選択ネットの表示はCSSによる端子ハイライト方式で、基板の拡大・縮小時にも追加の座標計算を必要としません。基板外のIC詳細パネルは拡大・縮小の対象外です。縦方向のページスクロールは従来どおりです。

## 操作画面の配置

- 「電源ON」「電源OFF」「停止／実行」ボタンとCYCLESはHARDWARE WORKBENCHの「TD4 ボード」タイトルと**同じ見出し行**に右寄せで配置し、その行の下に区切り線を描画します。別段の操作バーは設けません。狭い画面では見出し内で折り返して区切り線より上に保持します。「1クロック」「リセット」ボタンと速度プルダウンは撤去し、クロック周波数は基板スイッチのみで設定します。
- PROGRAM ROMではPC／ブレークポイントの凡例と「BPを解除」をROMテーブルの見出し行より上に配置し、操作説明文は表示しません。
- LOGIC ANALYZERでは「波形を消去」を表示信号セレクタの右に並べます。サンプル数の文字表示は省略しますが、内部の波形履歴は引き続き最大80サンプルです。

## 命令セットのビット・制御信号リファレンス

ページ下部の折りたたみ式命令セットは、参考画像に準じて標準12命令を説明付きの2段行で表示する。上位4bitは命令固定値、下位4bitは即値 `i3..i0`（固定命令では0000）。C列は命令実行**後**のキャリーを示し、ADD系のみ0/1となる。信号列は `SEL_B`/`SEL_A`/`LOAD_A_N`/`LOAD_B_N`/`LOAD_OUT_N`/`LOAD_PC_N` の順に、LOW有効のLd0〜Ld3を表す。

信号表のレベルは `TD4Circuit.levels()` の理想論理値との一致を自動テストで確認する。JNCのLd3は旧Cに依存するため `L/H` を併記し（旧C=0ならL、旧C=1ならH）、一律LOWと誤記しない。機械語の実行ロジック・12命令以外のデコードは変更しない。通常画面は表の固定最小幅を廃止して各セルを圧縮し、860px以下では1命令ごとに8bitと6本の制御信号を3段のレスポンシブグリッドで示す。どちらも横スクロールを必要としない。

## 基板の電源・CR発振切替

- 右列のROM 4×4・INPUT/OUTPUTの上に `POWER / CLOCK` 領域を新設して、ROMとI/Oを基板下方へ配置する。新領域は左側にCR発振回路＋2Hz/10Hzトグル、右側にPOWERトグル。電源パイロットLEDはPOWERスイッチの左、ON/OFFシルクはスイッチの右。シルク回路のCLK出力は左向きとし、部品記号のみ反転（文字は反転しない）。CRスイッチ下の重複した `CLOCK · 2 Hz` 表示は撤去する。
- 基板電源トグルはページロード時OFF。OFFからONへ操作した場合は既存の実行ボタンと同じ `run()` に入り、赤いパイロットLEDを点灯する。ONからOFFに操作した場合は停止ボタンと同じ `setPower(false)` でタイマーを停止、CPUレジスタと実行・波形履歴をリセットする。ただしROM内容と物理入力スイッチ設定は保持する。
- 基板のROM / FETCH、MUX / ALU、REGISTERS、CLOCK / CONTROLの機能見出しは英語表記のみとし、従来の日本語サブタイトルは生成・表示しない。4ブロックのシルク見出しは共通の11px・太さ800で統一し、ROM / FETCH専用の縮小指定は設けない（POWER / CLOCKの13px見出しは維持）。電源区画の重複補足シルク `TD4 CONTROL CIRCUIT` は削除する。ツールチップ・操作用アクセシビリティラベルは日本語のまま保持する。
- インバータ＋RC（CR）部品を簡略な基板シルクで示す。出力から抵抗Rを通して入力へフィードバックし、入力点からコンデンサCをGNDへ接続する。回路図上で無接続の入力線を伸ばさず、出力反転バブル（○）の内部に線を重ねない。シルクの `INVERTER` / `INV` 文字は表示せず、出力の `CLK` テキストは矩形パルス波形（Low→Highを2回繰り返す短い線画。抵抗の帰還配線と重ならないよう左側に収める）に置き換える。R/Cの文字は配線と重ならないよう配置し、ジャンクションは白の塗りつぶしで明示する。Rを上端で切らないようSVGのviewBoxを `0 -7 220 99` に広げる。これは物理ネットリストやアナログ発振動作の完全シミュレーションを意味しない。
- CR発振ブロックの切替トグルは**上側が10Hz・下側が2Hz**。読み込み時は2Hz（レバー下側）。CR/POWERの2区画は下部余白を減らしてコンパクトにまとめ、「MAIN SWITCH · DC」のシルクは撤去する。
- 見出し行は独立した「電源ON」「電源OFF」と、CPU実行状態に応じて「停止」または「実行」となる1個のトグル（計3ボタン）を設ける。Step/Resetボタン、速度プルダウン、手動クロックのSpaceショートカットは削除する。動作周波数は `boardClockHz` の2Hz/10Hzに一本化する。電源投入直後はPC=0x00で待機し、最初のクロック立ち上がりで番地0の命令を実行する（投入直後に即時実行しない）。電源断ではPCは0に戻すが、基板ROMのアドレス選択枠（`.rom-slot.is-current`）と選択LEDは点灯させない。
- 実行中に周波数変更した場合はインターバルを張り替えるが、再開時に余分なCPUクロック立ち上がりを発生させない。
- キーボード操作は電源ON中のSpaceでCPU実行／停止をトグルし（入力・ボタン操作中とキーリピートは除外）、EscはIC詳細表示中なら詳細を閉じる処理を優先する。詳細を閉じた際は操作元ICにフォーカスを戻し、詳細がない状態では既存のCPU停止ショートカットを維持する。
- `powerOn` とクロックのインターバル有無を独立させ、**電源OFF／電源ON・CPU実行中／電源ON・CPU停止中**を区別する。電源投入時は自動実行するが、ROMビット編集・ROM書込み・ブレークポイント到達・CPU停止ボタン・Escapeキーでクロックだけを停止し、VCC/パイロットLED/OUTPUT LEDの電源状態は保持する。電源OFF操作だけがCPUの揮発状態を初期化する。状態表示（ヘッダー）は3状態に追従し、停止中は琥珀色のドットとする。基板上のOUTPUT LEDは点灯時の発光色と光彩を強める。
- 電源OFF中はCPU/出力の動作を抑制する。無給電状態の真の電圧波形を表示するものではない。ブレークポイント等で一時停止しても、電源ONの表示は維持する。
- 制御状態は `src/ui/app.ts` が所有し、`src/ui/board.ts` はDOMイベントと描画のみを担当する。

## リファクタリング方針

- 命令実行・信号波形・ICネットのALU/MUXデコードは `TD4.decodeALU` を共有し、同じ命令ビットから同じ組み合わせ論理を計算します。既存のCommonJS/ブラウザ向けグローバル配布方式は維持します。
- `src/ui/app.ts` でCPUと波形の状態を管理し、波形SVGは初回に構築して信号パスのみ更新します。
- `src/ui/board.ts` では部品生成を補助関数に分け、基板の固定DOM参照と信号計算値をキャッシュします。ROMビットの信号はPCで変わるため、追跡候補を固定DOM全体から保持します。
- `src/**/*.ts` が唯一の編集元です。生成した `assets/js/**` は必ずコミットし、CIでビルド後の差分を検出します。
