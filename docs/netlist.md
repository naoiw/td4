## 参照と採用方針

- 添付 `TD4.pdf`（2021年KiCad回路図。p.1 CPU / p.2 ROM / p.3 CLOCK/RESET）
- https://xyama.sakura.ne.jp/hp/4bitCPU_TD4.html
- `src/core/ic-circuit.ts`・`src/core/signals.ts`（`develop`）

添付PDFと参考ページはROMのアドレス選択に **74HC138×2** を使用するが、オリジナルTD4は **74HC154×1**。本アプリは既存UIどおり **74HC154×1** を採用する。ROMスイッチは16組×8bit、出力には74HC540を使用する。

`U番号` はリポジトリの現行コードに従う。PDFとは一致しないので、以下の部品型番を照合して読み替える。

| U2 | 74HC14 | U13 |
| U3–U6 | 74HC161（A / B / OUT / PC） | U3–U6 |
| U7 / U8 | 74HC153（bit0–1 / bit2–3） | U8 / U9 |

## 直結する主要ネット

`U.pin` は**ICの物理ピン番号**。bitの並びはすべて下位bit=0。

| ネット | 接続先 |
| --- | --- |
| `CLK` | U3/U4/U5/U6.2, U1.11；クロック選択スイッチの出力 |
| `RST_N` | U3/U4/U5/U6.1, U1.13, U2.10（アクティブLOW） |
| `PC0..PC3` | U6.14/.13/.12/.11 → U13.23/.22/.21/.20 |
| `A0..A3` | U3.14/.13/.12/.11 → U7.6/.10, U8.6/.10 |
| `B0..B3` | U4.14/.13/.12/.11 → U7.5/.11, U8.5/.11 |
| `IN0..IN3` | INPUTスイッチ → U7.4/.12, U8.4/.12 |
| `MUX0..MUX3` | U7.7/.9, U8.7/.9 → U9.5/.3/.14/.12 |
| `D0..D3` | U12.11/.12/.13/.14 → U9.6/.2/.15/.11（加算器B入力） |
| `ALU0..ALU3` | U9.4/.1/.13/.10 → U3/U4/U5/U6 の各.3/.4/.5/.6 |
| `OUT0..OUT3` | U5.14/.13/.12/.11 → OUTPUTポート、LED表示（LEDは抵抗経由） |
| `COUT` | U9.9 → U1.12（74HC74のB側D入力） |
| `C_N` | U1.8（74HC74のB側 /Q）→ 分岐・ジャンプ条件 |
| `SEL_A` | U10.3（D4 OR D7）→ U7/U8.14 |
| `SEL_B` | D5 → U7/U8.2 |
| `LOAD_A_N` | U10.8 → U3.9 |
| `LOAD_B_N` | U10.11 → U4.9 |
| `LOAD_OUT_N` | U11.6 → U5.9 |
| `LOAD_PC_N` | U11.8 → U6.9 |

同じ `ALU0..3` の4本は、A/B/OUT/PCすべての74HC161のD0..D3につながる。書き込まれる先は各ICの `LOAD_*_N` によって決まる。A/B/OUTの74HC161はENP(7)・ENT(10)をGND固定し、PCのU6は両方VCCに接続して通常カウントを可能にする。

74HC153×2は `1E#(1)`・`2E#(15)` をGND固定。各4:1入力の `I0=A`、`I1=B`、`I2=INPUT`、`I3=GND` を選ぶ。選択線は `S0(14)=SEL_A`、`S1(2)=SEL_B`。

## ROM接続

- 74HC154(U13)：A0..A3は **23,22,21,20**、イネーブルは **18,19→GND**。
- アクティブLOW出力 `ROM_SEL_0..10` は U13.1..11、`ROM_SEL_11..15` は U13.13..17。
- ROMは1番地8bit、計16番地。各番地の8スイッチは同じ選択信号に**機能的**に属する。ただしダイオードを挟むため、選択線・各スイッチ下側端子・データ列は電気的に直結ではない。
- 74HC540(U12)：`OE1#(1)`・`OE2#(19)`→GND。ROMデータ列は、添付PDFの配線方向に合わせて **A7(9)=ROM_RAW0、A6(8)=ROM_RAW1、…、A0(2)=ROM_RAW7** と定義。出力は **Y7(11)=D0、Y6(12)=D1、…、Y0(18)=D7**。
- PDFの8連DIPスイッチを踏襲した場合、スイッチの各bit `b` の**上側端子番号は9+b**（例：bit0=9、bit7=16）。下側端子は**8-b**（bit0=8、bit7=1）。上側は全番地で共通の `ROM_RAWb` 列につながる。下側は各セル独立で、ダイオード経由でその番地の選択線に対応する。

ROMの論理データは `D0..D7`（74HC540の**反転出力**）。ROM_RAWとDを同じ電気ネットにしてはいけない。スイッチがONの場合、選択されたROM行がRAW列をLOWに引き込み、インバータ後に論理1となる関係としてモデル化する。ROMアドレス選択LEDは `ROM_SEL_i=LOW` で選択中とする。

## クロック、リセット、I/O、LED

- クロック：添付PDF p.3 は74HC14とRC発振・手動・外部入力の切替回路。抵抗・コンデンサをネットリストに展開せず、**選択後の `CLK` のみ**をCPU共通ネットとして確定。
- リセット：添付PDF p.3 の74HC14最終段（PDF U13E → アプリU2）の10番出力を `RST_N` とする。
- INPUT：`IN0..IN3` はスイッチの論理出力と74HC153のI2入力が共有するネット。電源/GND側の実端子は回路方式を確定するまで保留。
- OUTPUT：`OUT0..OUT3` はU5 Q0..Q3から出力端子へ接続する。LEDは電流制限抵抗を介して観測する**関連表示**として扱う（LED端子とOUTネットの直結は未確定）。
- ICのVCC/GND端子はそれぞれ単一の共通電源ネット。スイッチやパイロットLED、アナログRC回路の完全な物理配線は本版の対象外。

## 現行コードとの差と次の実装に必要なこと

1. `src/core/ic-circuit.ts` の74HC540物理ピンはY0をD0、Y7をD7と扱うが、添付PDFのU12は **Y7をD0、Y0をD7** としている。これを統一してからピン描画を共通データ化する。
2. 現行コードは74HC74のA側（1～6番）をキャリーFFとしているが、添付PDFは**B側（8～13番）**を使用し、B側の/Q（8番）をデコードへ接続する。正式な物理配線としてB側を採用する場合はUI側ピン定義を直す。
3. 現行の74HC161 ENP/ENTや74HC32/74HC10の多くの実ピンは未モデル化。少なくとも電源固定とゲート出力の確定済みネットは `netlist.json` に反映した。
4. 74HC32・74HC10の**各ゲート入力ピンと中間ノード**、クロック源切替回路のピンネット、INPUTスイッチの物理パッドは引き続き回路図上の線を追って確定する。
5. **物理ピンはJSONを正本として表示。** `pnpm run build` が `assets/js/data/netlist.js` を自動生成し、`physicalPins()` はその定義のみを参照する。ブラウザはJSONを直接fetchしない。ROMスイッチの共通RAW列も同じデータを参照する。機能プローブの仮想信号とCPU実行ロジックは従来どおり独立する。

## 表示上の注意

**電気ネット** と **機能的な信号関係** は区別する。

- 電気ネット：同一銅配線で常時直結される端子のみまとめる。
- スイッチ：閉じた状態の接点だけ接続される。
- ダイオード：信号伝搬はするが入出力を同一ネットに統合しない。
- 抵抗/LED：論理信号との関連表示として扱い、同一ネットへ強制統合しない。
- IC内部の入力→出力：内部論理の結果であり直結ではない。

この区別を守ると、ROMスイッチを操作しても無関係な行・列が「同一信号」としてハイライトされない。

## Webアプリの利用方針（2026-11）

- **接続の正本**は `src/data/netlist.json`。PDFを基準に端子・ネットを定義し、実装で同じ接続表を二重管理しない。
- `assets/js/data/netlist.js` はビルドで生成する公開用の読み取り専用データ。手動編集しない。
- ICの物理DIP脚はJSON `pinNets` / `pinNames` をそのまま表示。抵抗・ダイオード・スイッチ・IC内部回路越しの信号は別ネットを維持する。
- ROMスイッチは上側の共通 `ROM_RAWn` 列へ所属させ、旧実装の「選択中だけ `Dn` に接続」とする疑似表示を廃止。下側は独立 `ROM_CELL_addr_bit` を保持するが、別端子として描画する機能は今後の課題。
- `src/core/ic-circuit.ts` の `chips`・`layout` はCPUの**機能的な論理プローブ**。物理配線ではない。FFの論理値・命令実行は変えない。
- 74HC74はPDFのB側を使用。Q(9)は未結線、/Q(8)を `C_N` とする。74HC540のビット順はPDF準拠、出力イネーブル(1,19)はGND固定とする。
- 74HC32/74HC10の未定義入力やCLOCK/RESETの中間配線を推測で追加しない。JSONに情報がない脚は未モデル化として表示する。
