EDUCATION / 4-BIT CPU

小さなCPUの中で、何が起きているのか。

TD4が命令を読み、計算し、出力するまでを順番に理解するための技術資料です。実機風の基板を直接操作する場合はEmulatorに戻って試せます。

基本構造 4bitと2進数 命令実行の流れ CPUデータフロー デコード解説 命令セット プログラム実行例 74HC ICの役割 IC詳細・ピン配置 演習 よくある疑問

01 / ARCHITECTURE

TD4の基本構造

TD4は4bitの値を扱う小さなCPUです。プログラムは16番地×8bitのROMに保存され、各命令は1バイトで構成されます。PC（プログラムカウンタ）が次に読むROM番地を指します。

A / B4bit × 2演算に使うレジスタ
PC4bit次の命令番地 0〜F
ROM16 × 8bit16命令を保存
C1bit加算結果のキャリー
INPUT4bit外部スイッチ
OUT4bitLEDに対応する出力

A/B・PC・OUTなどは74HC161、キャリーは74HC74の論理モデルで表現しています。電圧や伝搬遅延まで再現する回路シミュレータではありません。

02 / BINARY & HEX

4bit・2進数・16進数の読み方

1bitは 0か1 を表します。4bitを並べると 0000〜1111 の16通りの値を表せます。TD4では4bitの値を、短く書ける16進数（0x0〜0xF）でも表示します。

10進数00000₂0x0
10進数50101₂0x5
10進数101010₂0xA
10進数151111₂0xF

各bitの重みは左から 8・4・2・1 です。例えば 1010₂ は「8 + 0 + 2 + 0 = 10」、16進数では 0xA になります。

EXAMPLE · 4bit OVERFLOW

14 + 3 = 17 の結果はどうなる？

1110₂+0011₂=10001₂

計算結果の 10001₂ は5bit必要です。TD4のA/Bレジスタに保存するのは下位4bitの 0001₂（1）だけで、あふれた上位1bitがキャリーフラグ C=1です。

つまり MOV A, 14 → ADD A, 3 の結果は A=1、C=1 になります。この動作はエミュレータの「4bit加算」サンプルで確認できます。

03 / INSTRUCTION CYCLE

命令を実行するまでの4段階

01 · FETCHROMから取得PCが示す番地の8bitを読む
02 · DECODE入力元と書込先を選択命令上位4bitでMUXと制御信号を決める
03 · EXECUTE4bit加算器で演算選んだ入力元に下位4bitの即値を加える
04 · WRITE BACK状態を更新A / B / OUT / PCとCを更新する

通常は命令実行後にPCが1進みます（Fの次は0）。JMPは指定先へ移動し、JNCは命令実行前のCが0なら指定先へ分岐します。

04 / DATA PATH

命令ごとのCPUデータフロー

TD4の論理回路を簡略化したデータフロー図です。命令を切り替えると、MUXが選ぶ入力元、ALUを通る経路、実際に書き込まれるレジスタ、キャリーフラグの変化を比較できます。配線図ではなく、データと制御の流れを理解するための概念図です。

命令取得選択された入力書き込みキャリー制御信号
命令 / 機械語ADD A, 3（A=5）0x03
MUX入力・選択信号A = 5SelB=0 / SelA=0
ALU：入力元 + 即値5 + 3Im=3 → 1000 (8)
書込先A ← 8Aへロード
PCの更新通常実行：PC ← PC + 1次PC: 0011
キャリー (74HC74)COUT=0 → C=0旧C=0

Aの5と即値3が加算器に入り、8がAへ書き戻されます。PCは+1で次の番地へ。

読み方：制御信号（SelA/ SelB、LOAD_*_N）は上位4bitから決まります。データパスは常にALUまで計算しますが、JNC不成立時にはPCへのロードは行われません。COUTは加算器の組合せ出力、Cはクロックで74HC74が保持した値です。JNCの条件判定には実行前のCを使います。

図のICを詳しく調べる場合は74HCロジックIC詳細、命令バイトと制御信号の対応は命令セットを参照してください。実際の論理状態はEmulatorのSTEP実行でも確認できます。

命令の上位4bitを op、下位4bitを Im として、TD4の回路は入力元・演算・書込先を決めます。

実際の書込み信号はアクティブLOWです。PCの更新はJMP/JNCの条件も考慮します。

演算sum = source + Imresult = sum & 0xFC = (sum > 15) ? 1 : 0
EXAMPLE · ADD A, 3

A = 5 のとき

ROM 0x03→MUX A = 5→ALU 5 + 3→新しいA 8

結果は4bitに収まりC=0。PCは次の番地へ進みます。JNCなら、次の分岐先を選ぶ判定には更新前のCを使います。

標準12命令以外の機械語でも、エミュレータの命令コアは74HC153・74HC283などのデコードに従って処理します。

Cは命令実行後のキャリーフラグ。ADDのみ演算結果で0 / 1に変わります。JNCの分岐判定には実行前のCを使用します。

Ld0〜Ld3はアクティブLOW（Lで書き込み有効）、順にA・B・OUT・PCの制御信号です。JNCのLd3は旧C=0ならL、旧C=1ならHです。

ここにない機械語もハードウェアのデコードに従って実行できますが、オリジナルの標準12命令には含めていません。ICの伝搬遅延や接点チャタリングは模擬しません。

07 / STEP-BY-STEP

1命令ずつ実行して、レジスタの変化を追う

TD4のプログラムは、PCが示すROMの1命令をクロックのL→H（立ち上がり）で実行します。実行後にPCが次の番地へ進み、次の立ち上がりまで状態を保持します。以下はCPUをリセットした状態（A=0、B=0、OUT=0、C=0、PC=0）からの実行例です。

例1：Bレジスタの値をLEDに表示する

MOV B → OUT B → ADD B → JMP の繰り返しです。エミュレータで電源をONにして「停止」を押し、PROGRAM EDITORに次の4行を貼り付けて「ROMに書き込む」を押すとPC=0に戻ります。その状態からSTEPで確認できます。

MOV B, 3
loop: OUT B
      ADD B, 1
      JMP loop
STEP実行前PC命令実行後B実行後OUT次のPC
10x0MOV B, 3300x1
20x1OUT B330x2
30x2ADD B, 1430x3
40x3JMP loop430x1
50x1OUT B440x2

ポイント：Bが変わってもLEDのOUTがすぐに変わるわけではありません。OUT Bを実行して初めて、Bの値がOUTに書き込まれます。ここではどの命令も桁あふれしないためC=0です。

例2：キャリーがあるとJNCはジャンプしない

サンプルプログラム「キャリーと分岐」の最初の4命令を確認します。JNCは実行前のC=0のときだけ分岐します。JNC自身の実行後にはC=0になります。

MOV A, 15
ADD A, 1
JNC skip
OUT 15
end: JMP end
skip: OUT 0
      JMP end
STEP実行前PC命令実行後A実行後C次のPC
10x0MOV A, 151500x1
20x1ADD A, 1010x2
30x2JNC skip000x3
40x3OUT 15000x4

3番目の命令が実行される直前はC=1なので、JNC skipでは分岐せずPCが0x3へ進みます。その後の OUT 15 でLEDがすべてONになります。JNC実行後のC=0を見て分岐したと勘違いしないことが重要です。

10 / HANDS-ON

エミュレータで試す4つの演習

説明を読んだら、まず自分で次の状態を予想し、そのあとエミュレータで確認してください。各演習はサンプルプログラムか標準機能だけで試せます。STEPで最初から追う場合は、電源をONにして「停止」を押し、PROGRAM EDITORでサンプルを選び直してください。ROMが再読み込みされ、PC=0に戻ります。

01 / 入門 · LED

LEDスキャナの出力を予想する

PROGRAM EDITORの「LEDスキャナ」を選び、STEPで進めます。OUT 1 → OUT 2 → OUT 4 でLEDはどう変化するでしょうか？

答えと確認ポイント

OUTは1 → 2 → 4、2進数では0001 → 0010 → 0100です。1つずつ違うLEDが点灯します。OUT命令ごとにCは0になります。

02 / 入門 · INPUT

スイッチを変えたらいつLEDが変わる？

「スイッチ入力」を選び、INPUTを例えば 0101 にしてSTEPで実行。IN B の直後と OUT B の直後を比べてください。

答えと確認ポイント

IN BではBに5が取り込まれますが、OUTは変わりません。次のOUT BでOUTが5に変わり、LED0とLED2が点灯します。

03 / 中級 · JNC

桁あふれの直後はどこへ進む？

「キャリーと分岐」を選択し、ADD A, 1 の次のSTEPでPCがどこに進むか予想します。JNC実行後のC表示にも注目。

答えと確認ポイント

ADD後のCは1。JNCはその旧Cを見て分岐せず、PC=0x3に進みます。JNCの実行後はC=0に更新されます。

04 / 中級 · 波形

クロックの立ち上がりと停止を観察

10Hzで実行し、LOGIC ANALYZERのCLKとPCの変化を観察します。TRIGGERをONにしてCLKのL→Hを指定したとき、何が止まるでしょうか？

答えと確認ポイント

指定エッジで波形取得が固定（TRIGGERED）されますが、CPUの自動実行は続きます。CPUを停止するにはCPU側の「停止」を使います。

11 / FAQ

TD4を動かすときによくある疑問

4bit CPUなのに、命令が8bitなのはなぜ？

4bitはA/BレジスタやALUが扱うデータの幅です。TD4では命令の幅は8bitで、上位4bitに操作の種類、下位4bitに即値を収めています。データ幅と命令幅は同じでなくても構いません。

INPUTスイッチを変えただけでAやBは更新される？

いいえ。INPUTは外部入力の現在値です。IN AまたはIN Bなど、入力値を読み取る命令を実行した時点でレジスタに反映されます。

キャリーフラグCは、一度1になったら保持される？

いいえ。TD4では各命令の加算結果に応じてCが更新されます。例えば桁あふれでC=1になっても、次のJNCは分岐判定に旧Cを使ったあと、実行後のCを0に更新します。

プログラムを終了する命令はある？

標準TD4の12命令には専用の停止命令がありません。永続的に同じ位置へジャンプするend: JMP endで実質的に待機させるか、画面の「停止」でCPU実行を止めます。

波形に実際の電圧やゲートの遅延が表示される？

いいえ。表示されるのはモデル上の論理H/Lです。電圧・遅延・チャタリングは再現しません。また、波形は直近80サンプルなので長時間の履歴を保存する用途ではありません。
